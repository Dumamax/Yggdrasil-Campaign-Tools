# Yggdrasil Campaign Tools: notes for Claude

The canonical lore and design decisions live in the claude.ai Project **"D&D - Yggdrasil"** (`claude/World Bible.md`, `claude/Price Reference.md`, `claude/Guild Upgrade Catalog (draft).md`). If you can't reach it, ask Max for the latest World Bible before changing game rules or content.

## What this is
A single-file HTML app ("Guild Hall"), hosted on GitHub Pages from this public repo (root `index.html` redirects to `dist/`) and also usable offline as a downloaded file. Opens in a read-only **Player View**; the DM unlocks **DM View** with a password for prep and the table. The DM does not have Claude; Max does. Data must never depend on Claude-hosted storage.

## Build
`python3 build.py` concatenates `src/` into `dist/Yggdrasil-Guild-Hall.html` (commit `dist/`, since the DM downloads it from GitHub). It also gets published as a claude.ai artifact for Max (declare capabilities `sample` + `downloads`).

## Architecture (src/)
- `core.js`: helpers, campaign state `C` (+ `S = C.settings`), `commit()` (debounced autosave via `persist()`: localStorage, or IndexedDB kv `campaign` when the campaign is too big, flagged by `ygh.store`; + dirty flag), campaign file save/load/import, `AI` (artifact `sample` → API key via direct browser fetch → copy/paste fallback via `aiRun`/`aiButtons`), `printHTML` (window.print standalone; downloads a printable page when framed).
- `jobtables.js` / `upgtables.js`: default tables (`DEFAULT_JOB_TABLES`, `DEFAULT_UPG_TABLES`, `DEFAULT_PRICES`). Custom tables are stored in `C.tables.*` (null = use defaults) and travel in the campaign file.
- `jobboard.js` (`Jobs`), `upgrades.js` (`Upgrades`), `roster.js` (`Roster`): IIFE modules, each with `render`/`bind`.
- `shoptables.js` (`DEFAULT_SHOP_TABLES`) / `shops.js` (`Shops`): Shop Generator tab (`tab-market`; the `shop` tab id is Guild Upgrades). Shops live in `C.shops` (kept ones feed Print and Table Mode; unkept capped at 8); custom ideas and write-ups go through `aiRun`/`aiButtons`. Prices stored in gp decimals (0.1 = 1 sp), shown via `Shops.coins`.
- `npctables.js` (`DEFAULT_NPC_TABLES`) / `npcs.js` (`NPCs`): Roster → NPCs subtab. One people store: `C.roster` holds guild members (kinds Founder / Active PC / Retired PC / Hired NPC, shown under Guild Members; `Roster.sorted()` returns members only) and everyone else (kind `NPC`). NPC fields: `img` (one image, WebP ≤1000px via `PCs.shrink`; card thumbnail + full view `NPCs.openBig`, players get `publicHTML` only), `shown` (Player viewable → "Notable Figures" in the Player Council tab, `NPCs.playerSection`), occupation, title, connection, genre, archetype, level, label, look, voice, manner, want, secret, attitude, guild, public, seat (Council tier), rival, pinned, `x` (write-up), `sb` (stat block). Generator weights blank fields (level curve in `levelCurve`). Council = NPCs with `seat`; starting members seeded once by `NPCs.ensure()` (`C.councilSeeded`), which also adds Mordecai's profile fields (`forms`, `motive`). Bridges: `fromPatron` (Kept/Final jobs auto-save; job cards have save NPC / use NPC / + guild), `fromOffer` (Peddlers), `fromStaff` (shop staff), `addToGuild` / `leaveGuild` (never touch the treasury). Table Mode "NPCs in play" and Print (NPC cheat sheet for pinned NPCs, player-facing Council Notice).
- `tableeditor.js` (`TableEditor`): form view over any table JSON (lazy collapsible sections; maps vs records via heuristics + `RECORD` set; labels/hints maps).
- `app.js` (`App`): nav, Table Mode, print center, settings (incl. backups list), quick search (Ctrl+K; `index()` + `go()`; cards carry `data-job` / `data-member` / `data-npc` / `data-id` (shops) / `data-upg` so search and `App.flash(sel)` can find them), boot.
- Saving: `saveCampaign()` writes to a linked file handle when the File System Access API exists (handle kept in IndexedDB `ygh`/kv); otherwise downloads. `IDB` also stores rolling backups (`backup(reason)`, DM only, last 25; small records in `backups`, data in kv `bk:<t>`, read via `backupData(b)`; deduped by `ygh.backupHash`). `replaceCampaign(c, reason)` backs up first; loading a file another way unlinks the handle so a different campaign never overwrites it.
- Job Board cards are collapsed by default (`UI.jobsOpen` per id, `UI.jobsAllOpen`); secondary actions live in a `details.more` overflow menu. Roster subtabs: members / npcs / council (`NPCs.render(mode)`).
- Phone layout: `App.layout()` sets `body.mobile` (auto under 760px via matchMedia, or `UI.layout` = phone/desktop from Settings → Display). All phone CSS is scoped under `body.mobile` at the end of `styles.css`; `#mainNav` becomes a fixed bottom tab bar. Icons are inline SVGs injected into `[data-ico]` elements (`ICONS` in app.js); labels live in `.lbl` (full) / `.slbl` (short), so click handlers on those buttons must use `closest()`, not `e.target.dataset`.
- Print: `printSections()` lists handouts (players' first, DM-only last); each is a `.pr-sec` starting on a new page (US Letter, .5in margins, `PRINT_BASE`). `paginate()` simulates breaks (blocks that mustn't split: notices, shops, cards, ledger `tbody` per upgrade, NPC boxes) to count pages; with Two-sided (`UI.print.duplex`) a blank page follows any odd-length section. Ink-friendly (`UI.print.ink`) wraps output in `.ink`: overrides in `PRINT_BASE` strip fills/shadows to black line-work (double rules, ❦ ornaments). New printable blocks should be added to the `paginate()` selector and `PRINT_BASE` avoid-break list.
- `standing.js` (`Standing`): guild standing points (display name/short label configurable in `S.cp`; don't hard-code "Contribution Points"). State `C.guild.cp` = `{pts, log[]}` (pts = progress toward the next rank; log entries Job/Deed/Adjust/Promotion/Demotion). Unit = a Standard job at the guild's rank = 3 × (rank+1) (matches job `contribution`); step cost = `S.cp.stepJobs[tier]` units, deeds = `S.cp.deeds[size]` units. Jobs: ⋯ menu Completed / Failed / Reopen (`h.done`). Promotion is a DM click, never automatic; leftover points carry over. Strip renders into every `.standing-host` (Job Board, Guild Upgrades, Table Mode); player print section "Guild Standing"; the Player View Guild tab adds a rank ladder (`ladderHTML`, Iron 3 → Platinum 1, via `printHTML({ladder:true})`).
- `access.js`: Player/DM View and GitHub sync. `isDM()` = `S.dmHash` matches `ygh.dm` in this browser (casual protection only; the campaign isn't encrypted). Player tabs `p-*` render read-only handouts from the print functions into `#tab-p` (`renderPlayer` in app.js); `body.player` hides every editing control and shortcuts. `Sync` (status shows the loaded save time; Settings shows GitHub vs device save times, app `BUILD` stamp from build.py (`Updater` compares it with the live Pages file on open/focus and reloads into a newer build; root index.html adds a cache-busting `?v=`), and `force()` = Load the GitHub save now) pulls `data/campaign.json` via the GitHub contents API (metadata; files over 1 MB download as `git/blobs/<sha>`, never the contents URL with a raw Accept header, which shares an ETag with the metadata and confused phone caches; anything without `app===APP_ID` is rejected) (players every 2 min, DM every 5; downloads the file only when its sha changed or `C.savedAt` ≠ `ygh.shaAt`, since tokenless players share 60 API requests/hour per network), and `saveCampaign()` commits it when this browser has a token (`ygh.ghtoken`, never in `C`); sha mismatch → conflict dialog (overwrite / load theirs). `ask()`/`modal()` are the dialog helpers. While a GitHub save runs, `savingUI()` sets `body.saving` (button shows a spinner + "Saving…") and repeat saves are ignored.
- `pcs.js` (`PCs`): play stats on PC roster members (`m.pc`: stats, ac, hp, speed, init, saves, senses, resist, langs, spell, attacks/features as text lines, portrait as a downscaled JPEG data URL so it travels in the campaign file to GitHub; `body` = optional full-body image (WebP up to 1000px, keeps transparency; JPEG fallback) shown on the big card instead of the portrait). Edited in the roster editor ("Play stats"), imported via the Guild Hall Import Format (`PCs.fromImport`). Table Mode = `tm-layout`: Characters cards (`PCs.tableSection`, click → `modal(bigHTML,"pc-modal")`) as the main column, every other panel a collapsible `details.side-panel` in `.tm-side` (closed ones in `UI.tmClosed`). No personality/background on these cards. Players see the same cards (read-only, no Edit) in the Player tab `p-party`.
- Maps: `C.maps` = `[{id,name,img,hidden}]` (hidden = not in Player View; new uploads start hidden) (schema 6; images downscaled to 2400px JPEG via `PCs.shrink` and stored in the campaign). Managed in the DM **Maps** tab (`tab-maps`, `renderMaps`: upload, open, players-can-see, link to a world via `m.worldId`; world cards show their maps); players see them in the `p-map` Player tab, with `openMap()` (wheel/pinch/drag zoom viewer).
- Roster/NPC editor opens in place: `#editorHost` is parked in `#editorHome` while lists re-render (`Roster.park()`), then `Roster.place()` moves it right after the edited card. Lists with cards must re-render through `Roster.render`/`NPCs.render` (both park/place).
- Council re-rolls always set `guild` (`guildName()` from `T.guildNames`).
- `places.js` (`Places`, `DEFAULT_PLACES` = Settings table `places`): the Tree's gazetteer, one area per map (Bazaar districts, Heartwood Atrium, five Wards, Docks/Gatewood/Rootgate). Place tags c/m/n/g/k/o match patron categories, s = quest site. Jobs carry `giverAt` and `site` (`{a,p}` refs; site null for other worlds), shown on cards and notices (`noticeWhere`) and passed to Claude prompts. Also world-name tables by genre and gate IDs by distance, not tier (`Gate N-07` / `F-` / `X-` for the job's nearby / distant / far-flung location roll; Gatewood galleries Near/Far/Fringe).
- `worlds.js` (`Worlds`): `C.worlds` registry (schema 7), Roster → Worlds subtab. Marking a job Final in another world creates one (`Worlds.forJob`) and the patron NPC gets `worldId`; job cards can switch to an existing world.
- DM View is remembered per browser; Player View from DM View is a preview (`UI.preview`), and only Settings → Lock this browser forgets the password (`lockDM`).
- `notice.css` is shared by the page and print output (injected as `NOTICE_CSS`).

## Character import
Roster → Import character accepts the JSON in the project doc `claude/Guild Hall Import Format.md` (keep `Roster.mapMember` in sync with it), or a sheet's text/PDF sent through Claude.

## Conventions
- Everything the DM must keep lives in `C`; UI prefs in `ygh.ui`; API key only in `ygh.apikey` (never in `C`).
- Call `commit()` after every mutation of `C`. Each `commit()` pushes an undo snapshot (`UNDO`, session only); commits in the same tick coalesce into one undo step. Snapshots (`snap`/`unsnap`) keep big strings (images) once in `BIGL`, so undo memory stays small.
- Use `pickFresh(list, key)` (not `pick`) for anything players would notice repeating; recent picks are remembered in `C.recent`.
- When default tables change, bump their `version`; customized tables get an "Add new default content" merge (`mergeNew`) in Settings.
- `tools/` holds one-off content scripts (e.g. `content-v2.js`), already applied to `src/`.
- Keep the dark wood & gold look (Cinzel / Crimson Pro; print uses IM Fell parchment).
- Upgrade prices are in "jobs" = one Standard job's guild fee (25%) at mid-tier; `gp` overrides.
- Bump `SCHEMA` and migrate in `normalize()` if the campaign shape changes.
